# 2026-07-14 图像列表与回放性能提交说明

## 提交主题

```text
完善图像列表导出并优化序列回放性能
```

## 阶段目标

本阶段继续在 FPGA/PCIe 硬件尚未准备完成的条件下完善本地图像工作流，重点解决：

```text
多张图像无法切换和移除
图像列表缺少可辨识的缩略图
常用格式没有统一导出入口
2～3 帧固定序列重复读盘和重复转换
输入设置为 60 fps 时界面仍固定显示约 30 fps
无优化构建导致大图回放明显卡顿
```

改动继续遵守现有模块边界：原始图像和算法位于 `pa_core`，串口位于
`pa_transport`，列表、显示和交互位于 `pa_host`。未来 PCIe 图像源仍通过
`IImageSource -> ImageSession -> ImageView` 接入。

## 主要改动

### 1. 完善多图像列表

打开图像改为支持多选，并为每个列表项保存规范化的绝对路径。列表现在支持：

```text
点击项目切换当前图像
缩略图下方显示文件名
白色缩略图背景和灰色边框
按钮、Delete 键或右键菜单移除选中项目
多选批量移除
移除只影响列表，不删除磁盘源文件
移除最后一项时清空画布和状态信息
```

普通图像列表只保存路径与缩略图。切换项目时重新读取原始文件，避免打开大量
文件后所有 16-bit 像素长期占用内存。

### 2. 增加右键图像导出

图像列表右键菜单增加“导出当前图像”，格式语义如下：

```text
TiRaw     写出 16 字节 TiRayRaw 文件头和原始 16-bit LE 像素
RAW16 LE  写出无文件头的原始 16-bit LE 像素
PNG       写出当前窗宽窗位对应的 8-bit 显示图
TIFF      写出当前窗宽窗位对应的 8-bit 显示图
BMP       写出当前窗宽窗位对应的 8-bit 显示图
JPEG      写出当前窗宽窗位对应的 8-bit 显示图，质量为 95
```

原始格式通过 `QSaveFile` 原子提交，写入失败时不会留下半个目标文件。DCM 未使用
伪实现；需要等正式 DICOM 元数据、位深和编码要求确认后再接入。

### 3. 优化 TiRaw 显示和缩略图

窗宽窗位转换建立 65536 项查找表，逐像素阶段只执行指针读取和 LUT 查表，移除
原先每像素重复的边界裁剪和除法。

新增目标尺寸显示转换接口。图像列表缩略图直接从 16-bit 原始像素采样到目标
尺寸，不再先生成一张约 2548x3048 的完整 8-bit 图像后再缩小。

ROI 统计和 RAW16 导出改为直接访问连续像素指针，减少 `QVector::at()` 的重复
边界检查。

### 4. 针对固定 2～3 帧预加载回放

`LocalReplaySource` 启动时一次性加载全部有效回放文件，循环过程中通过 Qt 隐式
共享复用原始像素，不再重复访问磁盘和解析文件。

回放首帧使用可取消的成员定时器异步投递，避免 `start()` 内同步发帧造成重入。
停止、快速重启和回调内重启通过运行代际隔离，旧回调不能启动新一轮定时器。
非循环模式在最后一帧发出后再切换为停止状态，保证观察者收到帧时图像源仍有效。

### 5. 增加有界显示缓存

仅在固定内容的本地回放运行期间启用两层显示缓存：

```text
MainWindow  最多缓存 4 张窗宽窗位转换后的 QImage
ImageView   在 128 MiB 上限内缓存对应 QPixmap
```

这样第二轮回放起既不重复做 16-bit 到 8-bit 转换，也不重复做 `QImage` 到
`QPixmap` 的显示格式转换。调整窗宽窗位、停止回放、重新开始回放或切换静态图像
时会清空相关缓存。

该缓存明确不能按路径用于未来 PCIe 动态帧，因为硬件帧即使来源名相同，像素内容
也会变化。

### 6. 优化刷新节拍和统计

界面只保留最新待显示帧，不建立无界帧队列。新帧覆盖旧待显示帧时增加显示丢帧
计数，避免处理速度不足时延迟持续累积。

首帧立即提交。后续显示节拍跟随用户设置的 `1～120 fps`，使用累计纳秒时间基准
补偿 Qt 5 整数毫秒定时器误差。例如目标 60 fps 时会在 16 ms 和 17 ms 之间自动
调整，不再固定受 33 ms 上限约束。

状态栏显示“实际显示 fps / 目标 fps”。停止日志记录：

```text
输入帧数
实际显示帧数
显示丢帧数
加载失败数
```

全图 ROI 统计从首帧接收槽中移出，在显示提交后延迟执行，最多每秒调度一次，
并按固定回放帧路径缓存，避免重复扫描数百万像素阻塞界面。

### 7. 修正默认构建性能

Makefiles/Ninja 等单配置生成器在未显式设置 `CMAKE_BUILD_TYPE` 时，现在默认使用
`RelWithDebInfo`。该配置启用编译器优化并保留调试符号，不会覆盖用户或 IDE
明确指定的 `Debug`、`Release` 等配置。

真实 2548x3048 图像在无优化构建中的单图加载约 453 ms、显示转换约
36.4 ms/帧，是回放卡顿的主要原因。改为 `RelWithDebInfo` 后恢复到约 39 ms 和
4.1 ms/帧。

### 8. 增加真实性能基准工具

新增 `pa_image_benchmark`，在 `BUILD_TESTING=ON` 时构建。它不作为有时间阈值的
CTest 用例，避免不同机器性能造成测试不稳定。使用方式：

```sh
./build/pa_image_benchmark frame1.tiraw frame2.tiraw frame3.tiraw
```

工具输出固定序列预加载、单图加载、全尺寸显示转换、直接缩略图、全图 ROI 统计
和校验值，可用于后续比较 Qt 版本、编译配置和替换算法前后的性能。

### 9. 补充自动测试

测试新增覆盖：

```text
TiRaw 和 RAW16 LE 原始数据导出及重新加载
ImageSession 清空当前帧
缩略图目标尺寸显示映射
回放预加载后删除源文件仍可完成播放
坏文件预加载跳过和失败统计
快速停止并重启不会执行旧首帧回调
最后一帧投递期间图像源仍处于运行状态
```

## 当前边界

```text
远程桌面协议或显示器刷新率仍可能限制肉眼看到的帧率
状态栏 fps 表示应用提交到 ImageView 的实际帧率
高于机器显示能力时应用会丢弃中间帧，不积压延迟
PCIe 动态帧不能复用本地固定序列的按路径显示缓存
DCM 导出等待正式 DICOM 要求
FPGA 帧协议和正式 PCIe 图像源仍未接入
```
