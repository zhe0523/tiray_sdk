# TiRay 43108 客户集成手册

## 1. 交付范围

客户使用 C/C++ 业务接口控制平板：RS422 命令与 PCIe 收图由 SDK 内部完成。不要依赖未文档化的头文件字段，也不要解析通信帧。

| 客户应使用 | 客户不要使用 |
|---|---|
| `tiray_sdk_*`、设备控制、高层 Static/Dynamic 配置、模板流程、PCIe 收图 | 原始配置组 2/3/4、内部 profile、协议命令号、FPGA 地址表 |
| `tiray_status_string` | 把未文档化的设备字段当稳定 ABI |

C++ 类 `tiray::Sdk` / `tiray::PcieReceiver` / `tiray::AsyncJob` 是对 C API 的 RAII 封装，语义相同。对照见《API参考》。

## 2. 初始化

```cpp
tiray_sdk_config_t config;
tiray_sdk_default_config(&config);
config.rs422_device = "/dev/ttyWCH0";  // 指针必须在 Sdk 生命周期内有效
tiray::Sdk sdk(&config);
tiray_status_t result = sdk.open();
if (result != TIRAY_STATUS_OK) {
    std::cerr << tiray_status_string(result) << std::endl;
    return 1;
}
```

默认：波特率 115200、8N1、无流控、响应超时 500 ms、最多重试 2 次。`profile` 保持默认对外版。

`tiray::Sdk` 不可复制、可移动。销毁前必须 `wait`/`reset` 所有 `AsyncJob`。

## 3. 推荐状态机

```text
create/open RS422
    -> ping / status
    -> open PCIe -> start 回调 或 自管 wait_frame 线程
    -> get_static_config / get_dynamic_config
    -> 业务：static 单帧  |  dynamic 连续  |  模板制作
    -> stop dynamic（若已启动）-> stop PCIe -> close RS422 -> destroy
```

### 3.1 静态单帧

1. 已打开 PCIe 接收（回调或独立线程中的 `wait_frame`）。
2. `start_static` / `tiray_start_static_capture`。下位机在该命令返回前会跑完整次静态采图（曝光窗口 + 暗场窗口 + 两帧硬件），SDK 为此等待最多约 30 秒。PCIe 回调应在调用前已经 `start`。
3. 在超时时间内等待 `image_type == 0` 的一帧。
4. 回调返回前把像素拷贝到客户队列。

### 3.2 Dynamic 连续采集

1. `get_dynamic_config`，确认 `cycle > 0` 且 `image_start_addr <= image_end_addr`。需要改参数时用 `set_dynamic_config`。
2. `start_dynamic`。
3. 用 `query_dynamic` 看 `state` / `end` / `frame_count`；图像仍走 PCIe。
4. 结束时先 `stop_dynamic`，再停 PCIe。异常时同样先 stop 再读 status。

`cycle` 禁止为 0（SDK 返回 `INVALID_ARGUMENT`）。`step_high[10]` / `step_low[10]` 未理解含义时保持读回值。

### 3.3 暗场模板（Offset）

```text
offset_begin(total, valid, mode)
  -> offset_capture
  -> 轮询 calibration_status，直到 task_state 为成功(3) / 失败(4) / 取消(5)
  -> 成功后再 offset_build，并继续轮询直到结束
```

约束：`0 < valid_frames <= total_frames`；`mode`：`0` 静态，`1` 动态。失败先 `offset_cancel`。轮询间隔建议 100–200 ms。

### 3.4 亮场模板（Gain）

```text
gain_begin(levels, frames_per_level, defect_threshold)
  -> 对每个灰度级 gain_capture(level)
  -> 每级后轮询 cal_status
  -> gain_build -> 轮询至结束
```

`levels` 最多 16 个；`frames_per_level > 0`。失败先 `gain_cancel`。

### 3.5 模板上传查询

`upload_config` -> `upload_start` -> 轮询 `upload_status`。
`template_kind`：`0` 暗场，`1` 亮场。上传图像的 PCIe `image_type` 为 `1`。

## 4. PCIe 与内存责任

SDK 不维护客户级图像队列，也不替客户申请长期缓存。

| 路径 | 缓冲区谁提供 | 生命周期 |
|---|---|---|
| `tiray_pcie_start` 回调 | SDK 内部临时缓冲 | 仅回调期间有效。返回后指针失效。必须拷贝到客户容器 |
| `tiray_pcie_wait_frame` | 调用者设置 `frame->data` 与 `data_capacity` | 调用者全程拥有；容量至少 `rows * columns * 2` |

像素：小端 16 bit，行优先，无文件头。默认回退分辨率 7680 行 x 3072 列。不要在回调线程做重计算。

`image_type`：`0` 正常采图，`1` 模板上传图。

同一 `PcieReceiver` 上，`start` 运行期间不要再调 `wait_frame`。先 `stop` 再 `close`。

## 5. 线程与超时

- 每个 Sdk 的同步命令内部互斥，多线程同时调用会串行等待。
- 不要在 PCIe 回调里调用 RS422 命令。
- RS422 超时由 `retry.response_timeout_ms` 与 `max_retries` 决定；PCIe 等帧超时由 `wait_timeout_ms`（默认 1000 ms）决定。
- 仅 `ping_async` 为后台线程；完成后必须 wait 并销毁 job，才能销毁 SDK。

## 6. 建议超时（客户侧）

| 步骤 | 建议 |
|---|---|
| `ping` / 普通配置 | SDK 内部 500 ms ×（1+重试 2 次），应用层不必再套短超时 |
| 静态采图等到一帧 | 应用层 3–10 s（曝光 + 传输）；示例为 5 s |
| `cal_status` 轮询 | 100–200 ms 一次；Build 可能持续数分钟，用进度字段更新 UI |
| Dynamic 停止 | 先 `stop_dynamic`，再轮询 `query_dynamic` 至停止，最后停 PCIe |

把图像写成文件时只写 `data` 的 `data_length` 字节，不要写结构体本身。

## 7. 错误处理原则

每个 API 检查 `tiray_status_t`，文本用 `tiray_status_string`。详见《错误恢复说明》。

## 8. 验证清单

1. `open` + `ping` + `status` 成功。
2. PCIe `open` + `start` 成功。
3. `start_static` 后在数秒内收到一帧，字节数 = `rows * columns * 2`。
4. 退出顺序：`pcie.stop()` 再 `sdk.close()`。

对照示例：`examples/customer_demo.cpp`。
