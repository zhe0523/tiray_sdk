# 系统依赖与权限

## 平台

- 仅 Linux / 银河麒麟。CMake 在 Windows 上会直接失败。  
- 编译客户程序需要 C++17（若用 `tiray_sdk.hpp`）或 C99，以及 pthread。  
- SDK 以静态库形式提供，随应用一起链接。

## 设备节点

| 节点 | 用途 | `open` 失败时 |
|---|---|---|
| `/dev/ttyWCH0`（现场可能是 `ttyUSB*` / `ttyCH*`） | RS422 | `ls -l /dev/ttyWCH*`，确认驱动与线序 |
| `/dev/idma0_event_0` | 帧事件 | 确认 PCIe 驱动已加载 |
| `/dev/idma0_c2h_0` | 图像 DMA 读 | 同上 |
| 系统自动查找的 PCI `resource0` | 图像尺寸等元数据 | `create` 可能返回 NULL |

当前用户需要对这些节点有读写权限。长期使用 root 运行业务程序不安全。

## udev 示例

将安装文档中的 `99-tiray.rules` 拷到 `/etc/udev/rules.d/`：

```bash
sudo cp 99-tiray.rules /etc/udev/rules.d/
sudo udevadm control --reload-rules
sudo udevadm trigger
# 把业务用户加入 GROUP（示例为 dialout）
sudo usermod -aG dialout "$USER"
```

重新登录后再运行程序。

## 常见 IO_ERROR

1. 节点不存在：驱动未装或设备未枚举。`dmesg` 与 `lspci` 交给现场支持，不必在应用里扫描 PCI。  
2. `Permission denied`：udev/组未生效。  
3. RS422 `open` 成功但 `ping` 超时：波特率、接线、下位机服务未启动。SDK 不启动 `pa_controller`。  
4. 仅有命令成功、从无图像：PCIe 节点或事件设备未打开，或在发 `start_static` 前没有 `pcie.start`。

## 资源占用

一帧 RAW16 最大按回退尺寸约 `7680 * 3072 * 2` 字节。客户队列深度自行限制；队列满时由客户决定丢旧或丢新，SDK 不丢帧也不堆积。
