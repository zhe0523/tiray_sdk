# 常见问题

## 编译与链接

**`find_package(tiray_sdk)` 失败**  
CMake 找不到 `lib/cmake/tiray_sdk`。安装到非 `/usr/local` 时加上：

```bash
cmake -S . -B build -DCMAKE_PREFIX_PATH=/你的安装前缀
```

**undefined reference to `pthread_*`**  
`tiray::tiray_sdk` 已依赖 Threads；若手写 `gcc` 链接，需要 `-lpthread`，且 `libtiray_sdk.a` 写在 `-lpthread` 前面。

**只能在麒麟/Linux 编**  
Windows 上配置阶段会直接报错。不要用 MinGW 交叉当客户交付环境。

## 运行

**`open` 返回 IO_ERROR**  
串口路径不对或无权访问。`ls -l /dev/ttyWCH0`，按《系统依赖与权限》装 udev。路径用命令行传入，不要写死后再改源码。

**`ping` 超时，但串口能打开**  
下位机服务未运行、波特率不是 115200、或接线问题。SDK 不会启动 `pa_controller`。

**`PcieReceiver` 构造后 `open` 失败 / 程序一启动就退出**  
默认会查找平板 PCI 设备。工控机上没插卡、驱动未加载时 `create` 可能得到空句柄。先确认 `/dev/idma0_event_0` 存在。

**`start_static` 成功但收不到图**  
必须先 `pcie.open` + `pcie.start`（或自己循环 `wait_frame`），再发静态采图。命令成功只表示下位机接受“拍一张”，图像走 PCIe。示例默认等 5 秒。

**回调里拷贝后图像花了 / 崩溃**  
`frame->data` 在回调返回后无效。必须拷贝像素字节，不要保存 `frame` 指针。若拷贝了 `metadata`，把 `data` 改成指向你自己的 `vector`。

**回调里调用 `ping` / `start_static`**  
不要这样做。回调在 PCIe 线程，RS422 命令会阻塞该线程，可能丢后续帧。把工作抛到自己的队列。

**访问配置组 2/3/4 得到 INVALID_ARGUMENT**  
客户版故意不允许。用 `get/set_static_config` 和 `get/set_dynamic_config`。

**Dynamic `set` 返回 INVALID_ARGUMENT**  
`cycle` 为 0，或起始地址大于结束地址。先 `get_dynamic_config` 再改需要的字段。

**模板做到一半失败**  
先 `offset_cancel` 或 `gain_cancel`，轮询 `task_state` 到空闲/取消，再重新 `begin`。不要在失败态 `build`。

## 图像

像素为小端 RAW16，无文件头，大小 `rows * columns * 2`。可用示例里的 `latest_frame` 直接 `fwrite` 成 `.raw`，用支持 16bit raw 的工具按行列打开。
