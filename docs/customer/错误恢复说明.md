# 错误恢复说明

所有业务接口返回 `tiray_status_t`。先 `tiray_status_string`，再按下表处理。不要忽略返回值。

| 返回值 | 典型原因 | 建议 |
|---|---|---|
| `OK` | 命令被接受 | 继续。注意 `start_static` 成功不等于已经收到图像 |
| `INVALID_ARGUMENT` | 空指针、缓冲区小于 `rows*columns*2`、`cycle==0`、模板帧数非法、串口路径为空 | 修正参数后重试，不要循环硬打 |
| `NOT_OPEN` | 未 open，或已 close | 先 `open`；PCIe 与 RS422 是两个句柄，需分别打开 |
| `BUSY` | 采集/模板未结束，或 PCIe `start` 重复调用 | 等 `cal_status` 回到空闲，或先 `stop`/`cancel` |
| `TIMEOUT` | RS422 无匹配响应；或 PCIe 在 `wait_timeout_ms` 内无事件 | 状态未变可重试 1–2 次；连续超时则 close/open 串口并 `ping`。检查线缆与下位机进程 |
| `PROTOCOL_ERROR` | 响应内容或图像尺寸元数据异常 | 记录日志，读 `status`；不要改客户程序去“解析硬件”。联系支持并提供 SDK 版本 |
| `CRC_ERROR` | 链路干扰或波特率不一致 | 检查 115200 8N1、接地与线长；可重试。持续出现需查硬件 |
| `IO_ERROR` | 设备节点不存在、权限不足、PCIe 映射失败 | 见《系统依赖与权限》 |
| `DEVICE_ERROR` | 下位机拒绝；或对外版访问了组 2/3/4 | `get_status` 看 `last_error`。模板失败先 `cancel`。Dynamic 异常先 `stop_dynamic` |
| `INTERNAL_ERROR` | 线程创建或内存失败 | 进程资源排查；重启应用。若复现提供复现步骤 |

## 流程级恢复

- **模板失败**：对应 `cancel` → 轮询到 `task_state==0` 或 5 → 再 `begin`。不要在失败态直接 `build`。  
- **Dynamic 异常**：`stop_dynamic` → `query_dynamic` / `status` → 确认停止后再 `start_dynamic`。  
- **收不到图**：确认 PCIe 已 `start` 或独立线程正在 `wait_frame`，再发 `start_static`；等超时后再查 `IO_ERROR`/`TIMEOUT`。  
- **reboot 之后**：串口会话作废，重新 `close`/`open`，再 `ping`。
